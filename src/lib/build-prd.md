# ArTrail /build 产品需求文档（PRD）

> **版本：** v1.1（补充量化验收标准与优先级）  
> **整理日期：** 2026-11-23  
> **产品范围：** `/build` 构建游戏模式、互动影游模式，以及本页可触达的菜单、案例、资产模板和任务入口。  
> **文档属性：** 基于当前代码与页面核对的现状 PRD，附明确标注的后续建议；不是全部功能已上线的承诺。  
> **核对方法：** 读取页面及相关实现；浏览器检查两种模式、游戏案例提示词回填、互动故事提交提示。未在本次核对中发起付费或真实 AI 游戏生成、录音转写及资产生成。

## 1. 产品概述

### 1.1 产品定位

/build 是 ArTrail 的创作启动页，帮助用户从一句玩法或故事描述开始创建内容，或从案例、游戏资产模板寻找创作起点。它不是游戏编辑器本身：游戏的设计文档、美术资产、代码生成和试玩发生在后续 `/game` 工作区；像素资产生成发生在 `/asset-template`。

当前存在两个页面模式：

| 模式 | 地址 | 主要任务 | 当前交付边界 |
|---|---|---|---|
| 构建游戏 | `/build?mode=build` | 输入玩法，进入游戏工作区；浏览游戏案例；创建资产模板画布 | 游戏启动链路已接入真实生成能力，但创作类型、模型、项目设置未全部传递到生成服务 |
| 互动影游 | `/build?mode=story` | 描述故事；浏览六项创作能力和互动故事案例 | 输入与语音可用；发送尚未接入互动影游创作服务 |

**重要区别：** 页面里写着“可生成”“支持某引擎”或显示模型名称，不等于对应服务已经连接。本文对这类情况单独注明。

### 1.2 产品目标

1. 降低游戏创作门槛，让用户明确从哪里输入需求、如何开始。
2. 将“从零描述”“复用案例灵感”“从资产模板开始”三类起点放在一个页面。
3. 区分游戏与互动影游的布局和案例，避免相互混淆。
4. 通过共享任务入口，让用户能回到已经创建的游戏。
5. 避免把展示型能力、示例图片或本地设置描述为真实已执行的服务。

### 1.3 目标用户与场景

| 用户 | 核心需求 | 典型起点 |
|---|---|---|
| 非技术游戏创作者 | 用自然语言得到可试玩原型 | 在构建游戏输入框写玩法 |
| 游戏策划 / 原型设计者 | 快速表达操作、目标、规则和美术风格 | 参考游戏案例提示词 |
| 互动故事创作者 | 编写场景、分支和观众选择 | 切换互动故事模式 |
| 游戏美术 / 独立开发者 | 按参考图生成同风格素材 | 选择资产模板和像素风格 |
| 回访用户 | 查看既有创作任务 | 点击左侧任务列表 |

## 3. 页面信息架构

### 3.1 构建游戏模式


- 桌面侧栏宽 333px，在小于 `lg` 断点时隐藏；本页没有单独的移动侧栏抽屉。
- 主内容最大宽度 1240px，需求区域最大宽度 800px。
- 顶部随机小游戏区域高 380px。
- 游戏模式保持原有布局，不套用互动影游模式的居中标题与输入框专属视觉样式。

### 3.2 互动影游模式

```text
返回创作 + 创作 / 互动影游面包屑
ArTrail / INTERACTIVE STORY
互动影游创作
描述你的故事，AI 帮你生成可玩的互动影游
六项轻量能力条
```

- 主内容最大宽度 1200px，标题与输入区最大宽度 900px。
- 能力条位于标题、副标题下方，输入框上方；不用六张大型卡片。
- 不显示随机小游戏、探索游戏及八类资产模板。
- 案例桌面每行最多四项，小屏两列；当前只有“末班车”，不填充虚构案例。

### 3.3 URL 与默认状态

- 仅 `mode=story` 进入互动影游，缺省或其他值进入构建游戏。
- 两种模式可以直接打开和刷新。
- 刷新恢复 URL 中的模式，不恢复输入文字、所选类型、所选项目、模型或已选案例。
- 切换模式会重新创建输入框，导致原输入及设置重置；当前无未保存提示。
- 页签标题分别为“构建游戏 — ArTrail”和“互动故事创作 — ArTrail”；各模式有相应页面描述与分享元信息。

## 4. 需求输入框

### 4.1 文本输入

**用户故事：** 用户写一段游戏或故事需求，选择必要参数后开始创作。

| 项目 | 构建游戏模式 | 互动影游模式 |
|---|---|---|
| 标题 | 构建游戏 | 互动影游创作 |
| 副标题 | 从一个玩法开始，打造你的游戏世界 | 描述你的故事，AI 帮你生成可玩的互动影游 |
| 占位文案 | 我想做一款…游戏，玩家可以…，挑战是… | 描述你想创作的内容… |
| 默认类型 | 网页游戏 | 互动故事 |
| 默认项目 | ArTrail | ArTrail |
| 默认模型 / 深度 | deepseek-v4-pro / High | 同左 |
| 发送后 | 进入 /game 创建游戏 | 显示未连接创作服务提示，保留输入 |

**现状规则：**

1. 以 `trim()` 后文本是否为空决定发送按钮是否可用。
2. 提交时去掉文本首尾空格。
3. 没有显示字数计数，也没有输入框侧 `maxLength` 限制。
4. 后续创建游戏接口限制需求为 1–4000 字符；过长需求可能进入创建失败状态。
5. 默认表单提交发送；没有专门实现“Enter 发送 / Shift+Enter 换行”的快捷键规则。
6. /build 不显示 Skill 和添加附件按钮，也不显示积分消耗或画布切换按钮。
7. 底部左侧为“创作类型 → 项目 → 模型”；右侧为“话筒 → 发送”。窄屏允许布局换行。
8. 输入、菜单设置和参考案例均为当前页面状态，不应声称已经存入 Cloud。

### 4.2 游戏提交交接

```text
输入需求
→ 如有参考案例，前缀“基于《案例名称》继续制作：”
→ 进入 /game，携带 prompt、project、tab=canvas
→ 创建 Cloud 游戏记录与第一条用户消息
→ 地址替换为带游戏 id 的工作区地址
→ 更新共享任务列表缓存
→ 在工作区执行设计 → 图片资产 → 游戏代码
→ 可以进入 Game 试玩
```

**当前交接缺口：** 输入框内部创建请求含 `type / project / model / depth`，但 /build 导航只使用 `prompt` 与 `project`；创建记录仅接收 `prompt`。类型、模型与思考深度未进入生成调用，项目未形成真实项目归属。

### 4.3 互动影游提交

- 有效文本点击发送后不跳转，也不创建互动故事记录。
- 当前状态提示为“尚未连接创作服务，你的输入已保留。”
- 标题副文案表达的是产品方向，不能作为真实互动影游生成已经上线的依据。
- **建议 P0：** 保持清晰的未接入提示，接入真实流程后再定义故事记录、节点、预览、发布和恢复机制。

### 4.4 滚动收起 / 浮动展开

- 输入框滚出主内容上方后，收起为页面底部悬浮输入条。
- 悬浮条显示已有输入；为空时显示引导文字。
- 点击悬浮条展开完整输入框，并聚焦文本区域。
- 展开时有背景遮罩；点击遮罩或按 Esc 收起。
- 同一输入实例在收起 / 展开过程中保留草稿和菜单选择。
- 原位置保留占位高度，避免内容明显跳动。
- 回到原输入位置后恢复常规布局。

## 5. 第一个下拉菜单：创作类型

### 5.1 /build 独立目录

本页使用中文创作类型列表，不使用首页的 Web Game / 媒体生成列表。

| 顺序 | 类型 | 菜单说明 | 当前选择结果 |
|---|---|---|---|
| 1 | 网页游戏 | 浏览器里直接玩，HTML5、Phaser 或 Three.js | 游戏模式内更改选中项 |
| 2 | 互动故事 | 场景、选项和分支 | 切换到 story 模式 |
| 3 | 素材画布 | 在画布上做图片、视频和 3D 素材，不做游戏 | 当前留在游戏模式；没有打开素材画布 |
| 4 | Godot | 需要本机安装 Godot 4 | 当前仅更改选中项；不检查安装，不生成 Godot 工程 |
| 5 | 通用游戏 | 先不定引擎，让 agent 建议 | 当前仅更改选中项；没有引擎推荐流程 |
| 6 | TapTap Maker 游戏 | TapTap Maker 上的 UrhoX/Lua 游戏。在它的面板里登录，并新建或连接 Maker 项目。 | 当前仅更改选中项；没有登录或连接流程 |

### 5.2 操作规则

- 点击类型按钮向下展开，包含图标、标题、说明和当前选中标记。
- 选择项目后关闭下拉菜单。
- 游戏模式选择“互动故事”跳转到 `/build?mode=story`。
- story 模式选择任何非故事项跳转到 build 模式；由于输入框重新挂载，默认又显示“网页游戏”，不会保留刚选择的 Godot 等项。
- 游戏模式没有“More types…”；story 模式当前额外显示该入口，打开提供商设置。
- **重要：** 即使选 Godot / 通用游戏 / TapTap Maker / 素材画布，在当前游戏模式点击发送仍进入通用的网页游戏生成链路。

### 5.3 建议验收方向（未实现）

- P0：确保类型名称与实际交付一致；未接入类型不能静默生成另一种内容。
- P1：将类型写入 URL 或草稿，让切换和刷新保留用户选择。
- P1：为素材画布、Godot 和 TapTap Maker 定义真实入口、能力检查和输出格式。
- 不应把“本机需安装 Godot”等说明写成已完成的安装检测。

## 6. 项目选择

### 6.1 当前交互

- 点击“项目：当前项目”向下打开菜单。
- 搜索框支持对项目名称做不区分大小写的包含匹配。

**建议 P1：** 真实接入项目后，应明确项目 id、成员权限、游戏归属、切换时保留草稿及无权限项目处理；这些不是当前实现。

## 8. 提供商设置与添加提供商

### 8.1 提供商设置弹窗

入口：模型菜单设置图标；story 类型菜单“More types…”。

当前内容：

1. 搜索提供商名称。
2. 分类：全部、语言、图像、视频、3D、声音。
3. 默认模型展示：聊天模型在输入框选择；图像、视频下拉选项；3D 显示 Hyper3D。
4. 初始参考提供商：ArTrail-deepseed、火山引擎方舟、Hyper3D。
5. 提供商启用开关、配置按钮。
6. 热门提供商：OpenAI、Anthropic、OpenRouter，可打开配置表单。
7. 添加提供商入口。

**边界：** 启用开关、默认选项和提供商草稿均没有触发真实连接，也不改变生成服务；新增草稿不会自动进入主模型目录。

### 8.2 配置字段

| 字段 | 规则 |
|---|---|
| 显示名称 | 去首尾空格后不能为空 |
| 基本 URL | 必须为有效 HTTP / HTTPS 地址，不允许 URL 内含账号、密码 |
| 默认语言协议 | OpenAI聊天完成 / OpenAI Responses / Anthropic Messages / Google Gemini |
| 验证方式 | API密钥 / Bearer令牌 / 无需验证 |
| 凭据 | 密码输入，支持显示 / 隐藏；切换验证方式时清空；保存时不进入草稿 |
| 模型列表 | 模型 ID、显示名称、启用状态 |

### 8.3 模型管理

- “获取”当前不请求远程模型列表，显示未连接提示。
- 可以展开“手动添加模型”。
- 模型 ID 必填，同一草稿不允许重复；显示名称为空则使用 ID。
- 新模型默认启用，可切换启用状态或删除。
- 已启用模型数量随开关实时更新。
- 保存后新增 / 更新当前页面的非秘密草稿，显示“设置已暂存于本次页面；尚未连接模型服务，密钥未保存。”
- 取消 / 关闭不建立连接；凭据随表单卸载丢弃。

**安全要求：** 正式接入后，秘密凭据必须通过安全服务管理，不得保存到浏览器持久存储、URL、日志或可下载文档；需要独立定义连接测试和可用性反馈。

## 9. 语音输入

### 9.1 用户流程

```text
点击话筒 → 请求浏览器麦克风权限 → 录音
再次点击 → 停止录音 → 转写中 → 识别完成 → 文字追加到输入框
```

### 9.2 状态与规则

| 状态 | 表现 | 行为 |
|---|---|---|
| idle | 圆形话筒按钮 | 可开始录音 |
| recording | 话筒红色闪动；提示停止录音并识别 | 再次点击停止 |
| transcribing | 加载图标 | 重复点击不再次发起转写 |
| 成功 | 回到话筒 | 追加识别文字并聚焦输入框 |
| 失败 | 输入框下错误提示 | 保留原输入，可重试 |

- 原文本非空时，中间加空格后追加识别结果；不会自动发送。
- 当前录制为单声道 WAV，通过同源转写接口读取流式文字。
- 过短录音、无有效识别内容、权限拒绝和服务错误均有失败提示。
- 当前过短录音提示含“按住说话”，但实际操作是点击开始、再次点击停止；这是待统一的文案问题。
- 页面侧没有录音时长显示或明确最大录音时长；本 PRD 不虚构时长、费用或转写额度。
- 需 HTTPS 或本地安全环境及浏览器麦克风支持；本次未重新检查真实录音及中文识别准确率。

## 19. 产品结论

/build 当前已经具备清晰的游戏创作起点、真实后续游戏生成链路、案例灵感复用、像素资产画布入口和共享游戏任务列表；互动影游页具备完整的展示和输入入口，但还没有真实故事生成。

下一步应优先解决“用户所选参数与真实执行是否一致”，而不是继续增加入口：创作类型、模型、项目归属和案例按钮含义都需要与最终结果匹配。这是从可展示原型走向可交付产品的关键。
